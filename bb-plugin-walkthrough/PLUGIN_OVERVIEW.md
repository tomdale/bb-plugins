Understand a code change the way you would with a colleague walking you
through it. From any thread, open **Walkthrough** and a notebook page opens
beside the conversation: one part at a time, explained in plain prose with real
code excerpts, margin notes, and room to ask anything.

## What you get

- A page that reads like a notebook: a serif column, the part number in a ruled
  margin, notes in the margin (under the figure when the pane is narrow). No
  rail or contents list; a part picker in the top bar jumps anywhere.
- Figures the helper chose to show as a diff (with Diff, After, Before) or as
  current code. Each excerpt is saved when written, so it survives later edits.
- A pager with Previous, a named Next, and a question box scoped to the current
  part, with suggested questions the helper wrote.
- A **Concerns** sheet that gathers every note, todo, comment, and question you
  flagged, anchored to its part and line, without reflowing the page.
- A starter that says what it found: "PR #12 · title", "Uncommitted changes · 4
  files, +120 −30", or the branch's committed changes.
- A wrap-up ledger with one primary action for what you are doing: **Post
  review** (behind a confirmation), **Send open items to thread**, or **Save
  notes** to a Markdown file in the thread's storage.
- A full-page view for reading without the thread beside it.

## How it works

A helper agent forked from your thread writes the walkthrough, so it knows what
you were discussing; your thread keeps working meanwhile. It writes one part
ahead of you and streams each part as text, so the page fills in while it
writes. Nothing is posted to GitHub unless you confirm it, and nothing is
written to your repository.
