# Pi Todo renderer for BB

Renders completed Pi `todo` tool calls as a read-only card above BB's thread composer. The existing Pi extension remains the only author of todo state; this plugin registers no agent tool or CLI command, creates no separate todo database, and does not alter the agent's instructions. The card uses BB's composer `chrome: "card"` and shows progress, in-progress work, and tombstones hidden from view. It also works in queued-message and side-chat composers.

The server reads each thread's public event timeline in ascending pages, ignores unsuccessful tool calls, and reconstructs a snapshot for the plugin app over read-only RPC. It rejects incomplete scans rather than showing a partial plan. While an agent runs the card periodically refreshes; thread lifecycle signals and reconnects trigger additional refreshes. Snapshots are isolated by thread and computed from its own events, not a cross-thread store.

`@tomdale/pi-todo` supports `create`, `update`, `delete`, `batch`, `list`, and `get`, with pending/in_progress/completed/deleted statuses. A fresh cycle requires an atomic batch of at least two creates; a new batch after all tasks become terminal replaces that cycle without reusing IDs. Only one task may be in progress. Completed tasks cannot reopen; deleted tasks are tombstones. Successful query calls do not change the snapshot. The card preserves `parentId` and `blockedBy` when they occur in call arguments, nesting child rows and labeling unfinished blockers. **The current source extension's parameter schema does not declare either field**, so its runtime ignores them and its checkpoint sanitizer strips them. This renderer cannot reconstruct hierarchy or dependencies from actual `@tomdale/pi-todo` output until the source extension emits those fields (or BB exposes its structured result details). `activeForm` is likewise not part of the current source extension; it is displayed only when a producer emits it.

BB 0.44's first-party pending-todos card accepts only flat provider plan steps and is not plugin-writable. This plugin uses BB's native composer-card host chrome, with plugin-owned rows inside it, rather than claiming to populate that first-party data model. Pi's branch replay/checkpoint/reset history is not available in BB's tool-call event arguments; timeline replay reflects successful calls visible in the BB thread, not resets or branch edits elsewhere in Pi.

Run `npm test`, `npm run typecheck`, and `npm run build` here. Do not reload or install the live plugin without operator approval: replacing the installed generation changes its current behavior.
