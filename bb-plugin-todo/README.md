# BB Todo

A BB-native task list for each thread. The `todo` agent tool owns task state in the plugin database; the composer card and **Todos** thread panel read and edit that state directly. There is no dependency on Pi's Todo extension, tool-call event replay, or a provider-specific state format. New lists start empty; lists from older Pi Todo threads are not imported.

Tasks can be nested with `parentId` and sequenced with `blockedBy`. Creation and updates reject missing, deleted, self-referential and cyclic dependencies or parents. `addBlockedBy` and `removeBlockedBy` edit dependency sets incrementally. Only one task can be in progress; completed tasks cannot reopen and deleted tasks are tombstones. `list` hides tombstones unless `includeDeleted` is true. `clear` empties the list and resets IDs. Agent and UI changes go through the same reducer.

The UI has three surfaces. The composer card sits above the prompt (or in the thread's right gutter when it fits), titled with the active task's working label and a completed/total count; it expands while the agent works a task. The thread header's Todos button shows the same count and opens the **Todos** panel, which edits the list: a status menu per task that disables transitions the reducer rejects, inline subjects, a details disclosure for description, working label, owner and blockers, and a row menu for moving, nesting and deleting. On a subject field, Alt+Up/Down reorders siblings and Cmd+] / Cmd+[ (Ctrl elsewhere) nests under the previous sibling or moves out of the parent. Controls under `components/ui/` are vendored from BB's shadcn registry (`components.json`).

State belongs to its BB thread and persists across provider sessions and plugin reloads. A thread becoming idle settles unfinished `in_progress` tasks back to `pending`. Deleting a thread removes its task state. The composer card shows progress and unfinished blockers; an all-complete card hides after the configured delay.

Run `npm ci`, `npm run typecheck`, `npm test`, and `npm run build` from this directory. The repository's `scripts/bb-plugin-smoke` checks activation in a throwaway BB server. The daily app loads the plugin from the canonical `main/bb-plugin-todo` path, not a task checkout.
